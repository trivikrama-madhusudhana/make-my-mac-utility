# Four-model release evaluation

September 13, 2026. **Release judgment: ready for an initial public release of the skill.** The four supported model/client combinations completed consultation, three-option design review and native implementation, with concrete defects returned to their originating models and independently rechecked. No known blocker remains in the exercised paths. This is a recommendation to release the workflow, not a claim that every generated app or Mac environment is fully validated.

## What was tested

The supported matrix is Codex CLI 0.153.4 with Astra (`gpt-6-astra`) and Sol (`gpt-5.6-sol`), and Claude Code 2.1.270 with Opus (`claude-opus-5`) and Fable (`claude-fable-5-1`). Claude metadata includes Haiku housekeeping calls; the primary generation models are the ones named here. No further Grok tests were run. Earlier Grok results are historical and outside this release's support claim.

The [test contract](RELEASE-CANDIDATE-PLAN.md) and fictional-user facts were written before the runs. Astra and Opus received the same everyday tea-brewing problem; Sol and Fable received the same photo-naming chore. The evaluator answered consultation questions, reviewed all three HTML alternatives, requested concrete revisions, and supplied explicit simulated-user approval before native implementation. These are disposable evaluation tasks, not real user commissions. The evaluator did not repair generated native source: each app defect below went back to its originating model.

The model runs used a fixed skill snapshot. Final edits to consultation and recovery guidance were evaluated with separate response regressions; the original native runs are not relabeled as generation from the final text. Per-stage metadata retains the input skill hashes. The final package hash list is [final-skill.sha256](final-skill.sha256).

### Recovery and file-picker findings

Sol's original staging catch suppressed a failed restoration but reported that original names were restored. An independent two-file fault injection reproduced the false message while the first file remained under a hidden staging name. The repair tracks recovery failures in both staging and commit, preserves the bytes, and reports original/current locations. The same independent probe then produced an explicit incomplete-recovery message with the actual staged path. New model regressions cover both secondary failures. Original source and app archives remain locally preserved.

Sol's original file picker could select the same valid PNGs that worked in Fable's app but left Open disabled. A fresh process repeated the failure. After the model changed to a window-attached sheet and added standard Edit commands, native Open, rename and Undo succeeded. This supports the repair on this host; it does not establish that every use of `runModal()` is defective.

Fable's first native window exposed a layout problem absent from its HTML: long secondary folder text compressed INVENTORY CODE into five fragments. The repair preserves the selected dimensions, protects the label and input, and lets secondary text truncate. The evaluator saw a legible toolbar in both empty and selected-file states. The model's packaged-binary offscreen renders cover long content and error states; those renders are distinct from interactive GUI checks.

Opus's read-repaired app also lost keyboard focus after clicking Dismiss, although keyboard Return to Dismiss worked. The evaluator reproduced click-then-type twice. The model added a deferred AppKit first-responder update after the SwiftUI transition; data code and HTML stayed unchanged. In the final clean packaged app, actual mouse clicks on Dismiss, Cancel and Retry into empty state each sent the next typed character to Minutes. A repeated malformed-file check still preserved the exact bytes, and successful Retry remained read-only. The core suite again passed 404 checks; the evaluator confirmed that the independently probed core hashes were unchanged. Actual menu Quit was followed by process absence.

### Final skill refinements and response regressions

The reference for friendly consultation now loads before the opening response. A vague opening calls for one question or two closely related questions, with no speculative feature list. Failure semantics include Cancel, Dismiss and Undo, not only creating records. Native guidance requires accounting for failed restoration and checking text compression at the approved size. The final mouse-focus finding added an explicit check that both mouse and keyboard transitions return the next typed character to the intended field; this wording was validated structurally and its behavior checked in the repaired native app, not claimed as a fresh four-model generation run. A proposal cannot become agreement because the user has not objected.

AB–AF cover an unfamiliar fountain-pen workflow, vivid specimen-reference design, failed cancellation, secondary rollback failure and native label compression. The first diagnostic run included its criteria in the prompt; it is not a blind score. It exposed Fable's “otherwise record as agreed” wording, which was corrected in the guidance. AG then checked explicit proposal-versus-agreement handling across all four models. All four passed the relevant AB–AF response criteria in a fresh run without the scoring criteria in the model prompt (`final-release-blind`). Claude responses remained more verbose than Codex responses. All four explicitly retained proposal status in AG; Fable also retained it in the fresh AD response. These checks measure responses, not rendered design quality or native behavior.

### Existing data that cannot be read

An independent `StateStore` probe of Opus's first native build threw a read error but allowed writes. The app presented idle, then saved a new timer on Start (`saved=true`), confirming a path that could replace an existing unreadable timer. The repair explicitly approved by the evaluator preserves the file, blocks writes while state is unknown, and offers read-only Retry. Reset/Start Fresh is outside the fixture scope. Original source and archive are retained. In the repaired native window, launching with an evaluator-owned malformed file showed the message and Retry, with no Start/Cancel/Dismiss. Return Retry kept the malformed file byte-for-byte unchanged. After externally restoring the valid fixture, clicking Retry recovered Ready without changing any saved bytes. The core suite reports 404 passing checks and the offscreen native harness 48; those are model-run checks, distinct from these GUI observations. The independent probe against the repaired core now reports `phase=unreadable`, makes no write on Start, and retains that state. The evaluator also exercised revision 4 read failure and Retry in all three HTML designs: failed Retry stayed blocked; restored reads recovered the running countdown, Ready and empty inputs respectively.

AH response probes added a distinction between missing first-use data and existing unreadable data. All four rejected silent overwrite. Fable initially recommended backup-and-replace as a default; an initial clarification still left reset scope too loose. The final guidance identifies Reset/Start Fresh as a separate capability requiring approved scope, with read-only Retry as the default. In `read-failure-scope-final`, all four preserved unreadable data, blocked unsafe writes, distinguished missing data, required recovery verification, and kept reset out of scope unless separately chosen. No native action is inferred from these text responses.

## Evidence boundaries

These runs establish a reusable consultation/build/repair workflow across four named models and three distinct jobs when combined with the earlier Pocket Notes sprint. They do not establish a reliability percentage, universal support for arbitrary integrations, or identical output across models.

Codex Desktop was the evaluator surface for rendered HTML and native accessibility interaction. It reads the same skill as the CLI, but preview/question/automation capabilities can differ. This was not a separate blind Desktop generation run and does not claim every App/CLI configuration behaves identically.

Real system sleep, external-display removal, VoiceOver, Mission Control, Show Desktop, all Spaces/full-screen combinations, and complete menu-bar interaction coverage were not established in this sprint. Deadline reconstruction has automated coverage; Astra's observed lifecycle test was process restart, not a menu-Quit or sleep test. Closing/reopening via native automation can itself reactivate windows, so it is not scored as proof of every Dock lifecycle behavior. These environment-dependent checks remain explicit app handoff items.

The initial image seed had a bad PNG data CRC; it was replaced with generated, CRC-valid PNGs and the hash baseline was reset before scored file tests. Sol's repeated picker failure persisted with fresh valid files that worked in Fable. Python ZIP extraction initially omitted stored executable permissions; restoring the archived Unix modes resolved that harness launch failure. Intervening user input and intermittent CUA capture failures were refreshed or paused, not scored as app defects. No real user files were renamed.

This workspace's file provider reattaches Finder metadata to loose app bundles, invalidating strict signatures after packaging. Fresh local-only extractions of the delivered ZIPs pass strict code-signature checks. The archive is the verified artifact; a formerly verified loose bundle is not assumed unchanged. Models sometimes used temporary probe paths outside their requested fixture; those isolation deviations are retained in local logs and are not described as strict isolation.

Raw provider streams and personal workspace paths are excluded from the public package. The test plans, harnesses and this report are included; generated galleries are excluded. Run `run_artifact.py` for fresh artifact tasks, inspect the previews, and give a specific fixture approval before continuing. Native checks require a Mac and actual GUI interaction.

The unchanged packaging helper passed its four regression tests again, including moved-app resource loading and path/resource protections. Skill metadata validation also passed.

Fresh final-skill discovery passed in both clients: Codex located and read the installed skill by name; Claude invoked its Skill tool and read the consultation reference. No skill path or content was supplied in the user prompt. Claude's opening remained more verbose, so concise consultation is an improvement area rather than a claim of identical style.
