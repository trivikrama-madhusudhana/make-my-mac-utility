# Four-model release candidate

Declared before the fresh runs, September 13, 2026. Supported clients are Claude
Code and Codex; target models are Astra, Sol, Opus and Fable. Historical Grok
artifacts remain in the archive, but Grok is outside the release support claim.

## Release decision

Recommend public release of the skill when all four models have completed fresh
consultation, three-option HTML and approved native-build paths, with no unresolved
critical workflow failure; observed defects have appropriate regression evidence;
packaging, installation instructions and the review archive are current; and
remaining environment-dependent checks are stated accurately. This is a release
judgment about a guided workflow, not a guarantee that every generated app works
without debugging or every Mac feature has been tested.

## New tasks

- Astra and Opus: **Steep**, a tea-brewing countdown companion. Start from an
  everyday-language request, discover timing and invocation needs, then settle
  a single active timer, deadline-based timekeeping, completion, cancellation,
  persistence, recovery and quiet visual treatment with some personality.
- Sol and Fable: **Frame Names**, a local image-file renaming mini app. Start from
  the user's archive chore. Settle file selection, inventory prefix, numbering,
  before/after preview, collision handling, an explicit rename action and recovery.
  Work only on disposable example files. Request a vivid but readable visual style.

The evaluator plays the same fictional nontechnical user for both models on a
task, answering only the questions asked from a fixed fact sheet. Preserve exact
messages and responses; don't hand the agent a complete engineering specification
at the first turn. Engineering choices may be delegated; missing material choices
must remain questions. No native implementation until the evaluator has inspected
all three previews and sent a specific simulated-user approval for this fixture.

## Acceptance

1. **Consultation:** preserves the user's job, asks short relevant rounds, owns
   engineering choices, offers meaningful recommendations without false agreement.
2. **Design:** exactly three offline interactive designs; same accepted functions;
   meaningful structural differences; legible realistic content, focus and failure
   states; intentional hierarchy, proportions and taste appropriate to the request.
   Inspect at ordinary and narrow viewports and exercise all three main flows.
3. **Build:** correct category and selected appearance, packaged launchable app,
   meaningful tests of the job, actual keyboard and native interaction observed.
   Document toolchain problems separately from app defects.
4. **Timer:** no negative/stuck countdown, time derived from a persisted deadline,
   cancellation and restart, completion recovery across quit/relaunch, input errors,
   Show/Hide/Quit and focus. Observe covering, Show Desktop and Spaces where tools
   allow; external display removal and VoiceOver are explicitly NT if unavailable.
5. **Renamer:** preview performs no writes, supported file selection, unique names,
   collision causes no overwrite, successful rename and agreed recovery, failure
   handling, regular app presence and closing/reopening. Verify actual fixture bytes
   and paths before and after native operations.
6. **Handoff:** ordinary-language launch/use/recovery instructions, source, app,
   data location, and tested/unverified distinctions. No UI verified from compilation.

For any failure preserve originals, distinguish harness and product defects, then
ask the originating model to repair against the unchanged agreement. Change the
skill only for a reusable omission; rerun the affected check. Report repaired
passes separately from first-attempt passes. Material final-skill changes require
fresh related regression evidence; do not retroactively relabel old runs.

## Isolation and retention

Each run has its own directory and a fixed copied skill snapshot. No production
files, credentials, unrelated projects, startup settings, publication or installs
are involved. CLIs may build fixture bundles; the evaluator handles GUI testing
sequentially. Keep original HTML, every revision, selected approval and screenshots.
Expose a four-model release-candidate gallery alongside the original sprint archive. Subsequent repository cleanup retains these galleries locally and excludes them from the distributed source.
